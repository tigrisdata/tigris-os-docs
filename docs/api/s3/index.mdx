# S3 API Compatibility

Tigris is compatible with the AWS S3 API. You can use the standard AWS S3 SDKs,
tools, and libraries with Tigris.

The compatibility data on this page comes from the
[S3 API compatibility test suite](https://github.com/tigrisdata-community/s3-api-compat-tests)
(AWS Go SDK v2). Each run creates a temporary bucket, executes every operation,
and reports a pass or a fail for each one. The Tigris result is from a run
against `https://t3.storage.dev` on 2026-11-14 with the suite at commit
`6176906`. The Cloudflare R2 and Google Cloud Storage results are from an
earlier run with a TypeScript runner that covered 68 operations. That runner
also scored `DeleteObject` and `GetBucketAccelerateConfiguration`, which the Go
suite uses but does not score. Both operations work on Tigris.

| Provider                 | Passed | Failed | Total | Score |
| ------------------------ | ------ | ------ | ----- | ----- |
| **Tigris**               | 57     | 10     | 67    | 85%   |
| **Cloudflare R2**        | 48     | 20     | 68    | 71%   |
| **Google Cloud Storage** | 45     | 23     | 68    | 66%   |

The ten Tigris failures are the bucket policy, encryption, and notification
configuration operations, which return `NotImplemented`, the two versioning
tests (see [note 9](#note-9)), and the SSE-S3 test (see [note 1](#note-1)).

✅ = supported |

The complete list of S3 APIs is in the
[AWS S3 documentation](https://docs.aws.amazon.com/AmazonS3/latest/API/API_Operations_Amazon_Simple_Storage_Service.html).

An operation that Tigris does not implement returns `501 NotImplemented` with
the standard S3 error body. It does not fall through to another operation, and
it does not change the bucket or the object. See
[Operations that return NotImplemented](#operations-that-return-notimplemented).

### Notes

1. <span id="note-1"></span> **Encryption**: Tigris encrypts all data at rest
   automatically, and server-side encryption with managed keys is always on. The
   bucket encryption configuration APIs return `501 NotImplemented`. SSE request
   headers on object writes (`x-amz-server-side-encryption` for SSE-S3/SSE-KMS
   and `x-amz-server-side-encryption-customer-*` for SSE-C) are accepted but not
   applied, so customer-provided keys are not used.
2. <span id="note-2"></span> **Canned ACLs**: Only canned ACLs (`public-read`
   and `private`) are supported.
3. <span id="note-3"></span> **Conditional copy**: R2 supports UploadPartCopy
   but does not support conditional copy operations
   (`x-amz-copy-source-if-match`, etc.).
4. <span id="note-4"></span> **GCS ACL model**: GCS uses a different ACL
   permission model where permissions are concentric (WRITE implies READ).
   S3-style ACL XML is accepted but behavior differs from AWS S3.
5. <span id="note-5"></span> **GCS versioning**: GCS maps versioning to its own
   generation number system, which differs from S3 version IDs.
6. <span id="note-6"></span> **Bucket location**: `CreateBucket` accepts a
   `LocationConstraint` that names one Tigris region (`iad`), two regions
   separated by a comma (`iad,sjc`), or one geography (`usa`, `eur`). Omit the
   value or use `auto` for a global bucket. See [Creating a bucket in a specific
   location](/docs/buckets/create-bucket/#creating-a-bucket-in-a-specific-location).
7. <span id="note-7"></span> **RenameObject**: Tigris serves `RenameObject`
   (`PUT /bucket/key?renameObject` with `x-amz-rename-source`) for every bucket,
   with the destination and source conditions. On AWS the operation is limited
   to directory buckets. `RenameObject` is not part of the shared test suite.
   See [Renaming objects](/docs/objects/object-rename/).
8. <span id="note-8"></span> **Notifications**: Object notifications are
   configured in Tigris Dashboard, not with the S3 notification configuration
   APIs. See [Object notifications](/docs/buckets/object-notifications/).
9. <span id="note-9"></span> **Versioning**: Versioning is a property of the
   bucket that you set at creation with the `X-Tigris-Enable-Snapshot` header.
   `GetBucketVersioning` reports `Enabled` for such a bucket.
   `PutBucketVersioning` with `Status=Enabled` on such a bucket succeeds and
   changes nothing. A request to enable versioning on another bucket, to suspend
   it, or to turn on MFA delete returns `501 NotImplemented`. The test suite
   creates a bucket without snapshots and enables versioning on it, so its
   `PutBucketVersioning` test fails, and its `GetBucketVersioning` test fails
   because it calls `PutBucketVersioning` first. See [object versioning
   APIs](/docs/buckets/snapshots-and-forks/#using-object-versioning-apis).
