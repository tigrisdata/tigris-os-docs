# Listing Objects with User Metadata

An S3 listing returns the key, size, ETag and last-modified time of each object.
Tigris can include the user metadata, the `x-amz-meta-*` values set at upload,
in the same response. File system clients such as
[TigrisFS](/docs/training/tigrisfs/) read file mode, owner and group for a whole
directory this way instead of calling `HeadObject` per key.

## Requesting user metadata in a listing

Send `X-Tigris-List-Metadata: true` with a `ListObjectsV2` or `ListObjects`
request. `list-type=ext-v1`, the listing extension TigrisFS and geesefs use, has
the same effect.

```bash
curl "https://t3.storage.dev/my-bucket?list-type=2&prefix=photos/" \
  --aws-sigv4 "aws:amz:auto:s3" \
  --user "$AWS_ACCESS_KEY_ID:$AWS_SECRET_ACCESS_KEY" \
  -H "X-Tigris-List-Metadata: true"
```

Each `Contents` entry carries one `Metadata` element per value, named without
the `x-amz-meta-` prefix:

```xml
<Contents>
  <Key>photos/cat.jpg</Key>
  <LastModified>2026-11-13T18:55:17.000Z</LastModified>
  <ETag>"e496e4bb9905a7f84495ddea8e9368d7"</ETag>
  <Size>51234</Size>
  <StorageClass>STANDARD</StorageClass>
  <Metadata>
    <Name>owner</Name>
    <Value>alice</Value>
  </Metadata>
  <Metadata>
    <Name>mode</Name>
    <Value>33188</Value>
  </Metadata>
</Contents>
```

## Where the metadata comes from

The full metadata of an object lives in the regions that hold the bucket's data.
Every region also holds a global index of every object with the key, size, ETag,
content type and last-modified time.

A plain listing reads the global index and is complete from any region. A
listing that asks for user metadata reads the full metadata. Inside the bucket's
[location](/docs/buckets/locations/) that returns every object with its
metadata. Outside it there is no full metadata for the bucket, and the listing
returns no objects.

## Returning user metadata from every region

Create the bucket with the `X-Tigris-Global-User-Metadata: true` header. Every
object written to it then has its user metadata copied into the global index,
and a listing with `X-Tigris-List-Metadata` returns it from any region.

:::note

The option is set at creation and cannot be changed afterwards. It does not
apply to [forks](/docs/buckets/snapshots-and-forks/) or to buckets that are the
target of a merge, which list from the full metadata of their own region.

:::

func WithGlobalUserMetadata() func(*s3.Options) {
	return func(options *s3.Options) {
		options.APIOptions = append(options.APIOptions,
			http.AddHeaderValue("X-Tigris-Global-User-Metadata", "true"))
	}
}

_, err = client.CreateBucket(ctx, &s3.CreateBucketInput{

## Behavior

- User metadata reaches a remote region together with the object's index entry,
  so it appears there when replication delivers the object.
- The metadata is stored in every region. Large values slow down every listing
  of the bucket.
- `ListObjectVersions` and `HeadObject` are unchanged. Version listings are
  served by the bucket's own location, and `HeadObject` reads the full metadata.
