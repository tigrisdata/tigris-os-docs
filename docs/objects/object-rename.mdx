# Renaming Objects

import Tabs from "@theme/Tabs";
import TabItem from "@theme/TabItem";

Tigris renames an object without a rewrite of the data. Tigris keeps object
metadata in a metadata service, so a rename updates the metadata in place. The
rename is fast, and it costs one request.

You can rename an object in three ways:

- With the S3 `RenameObject` API. This is the standard API, and the AWS CLI and
  the AWS SDKs support it.
- With the `X-Tigris-Rename: true` header on a `CopyObject` request. This is a
  Tigris-specific form. Use it with an SDK that does not have `RenameObject`.
- In Tigris Dashboard.

## Renaming objects with the S3 RenameObject API

`RenameObject` is `PUT /bucket/key?renameObject` with the source object in the
`x-amz-rename-source` header. Tigris serves it for every bucket. On AWS, the API
is limited to directory buckets.

The request renames `source-key` to `new-key` in the same bucket:

<Tabs groupId="languages">
<TabItem value="cli" label="AWS CLI" default>

```bash
aws s3api rename-object \
  --endpoint-url https://t3.storage.dev \
  --bucket my-bucket \
  --key new-key \
  --rename-source /my-bucket/source-key
```

A successful rename returns `200 OK` with an empty body. After the rename, the
source key does not exist, and the new key has the same content, ETag, and
metadata.

### Rules

- The source and the destination must be in the same bucket. The
  `x-amz-rename-source` value is `/bucket/key`, URL-encoded.
- The source cannot name a version. A `versionId` in the source is rejected with
  `400 InvalidArgument`.
- A rename to a key that exists replaces that key, as `CopyObject` does. To
  refuse the replacement, send `If-None-Match: *`. See
  [Conditional rename](#conditional-rename).
- The AWS CLI and the AWS SDKs send an `x-amz-client-token` header with each
  request. Tigris accepts the header and does not use it.

:::note

Tigris does not de-duplicate a retry of a rename. A retry after a successful
rename finds no source and returns `404 NoSuchKey`.

:::

### Conditional rename

`RenameObject` accepts conditions on the destination and on the source. Tigris
checks all of them in the rename transaction, so the objects the conditions
describe are the objects the rename moves and replaces.

| Header                                    | Applies to  | Behavior                                                                   |
| ----------------------------------------- | ----------- | -------------------------------------------------------------------------- |
| `If-Match`                                | destination | The rename proceeds only if the destination ETag matches.                  |
| `If-None-Match`                           | destination | Use `*` to rename only if the destination does not exist.                  |
| `If-Modified-Since`                       | destination | The rename proceeds only if the destination changed after the date.        |
| `If-Unmodified-Since`                     | destination | The rename proceeds only if the destination did not change after the date. |
| `x-amz-rename-source-if-match`            | source      | The rename proceeds only if the source ETag matches.                       |
| `x-amz-rename-source-if-none-match`       | source      | The rename proceeds only if the source ETag does not match.                |
| `x-amz-rename-source-if-modified-since`   | source      | The rename proceeds only if the source changed after the date.             |
| `x-amz-rename-source-if-unmodified-since` | source      | The rename proceeds only if the source did not change after the date.      |

A failed condition returns `412 Precondition Failed`, and nothing moves. An
`If-Match` on a destination that does not exist returns `404 NoSuchKey`, as a
conditional `PutObject` does.

### Permissions

A rename needs the same permissions as a copy plus a delete:

- `s3:PutObject` on the destination key. AWS defines no `s3:RenameObject`
  action.
- `s3:GetObject` and `s3:DeleteObject` on the source key.

A bucket role of `Editor` or higher grants all three. A key with `ReadOnly` on
the source bucket cannot rename objects out of it.

## Renaming objects with the X-Tigris-Rename header

Before `RenameObject` existed, Tigris used a `CopyObject` request with the
`X-Tigris-Rename: true` header. This form still works, and it returns a
`CopyObjectResult` body. Use it with an SDK that does not have `RenameObject`.

```
X-Tigris-Rename: true
```

<Tabs groupId="languages">
<TabItem value="go" label="Go" default>

```go
func WithRename() func(*s3.Options) {
	return func(options *s3.Options) {
		options.APIOptions = append(options.APIOptions, http.AddHeaderValue("X-Tigris-Rename", "true"))
	}
}

// rename the object in the bucket
_, err = client.CopyObject(ctx, &s3.CopyObjectInput{
   Bucket:     aws.String(bucketName),
   CopySource: aws.String(bucketName + "/" + keyName),
   Key:        aws.String(targetName),
}, WithRename())
if err != nil {
   log.Fatalf("Unable to rename object. Here's why: %v", err)
}
```

</TabItem>
<TabItem value="js" label="JavaScript">
Add the header to the S3 client middleware stack for the rename operation:

```js
export const renameObject = async (S3, bucket, oldKey, newKey) => {
  S3.middlewareStack.add(
    (next) => async (args) => {
      // eslint-disable-next-line no-param-reassign
      args.request.headers["X-Tigris-Rename"] = "true";
      return next(args);
    },
    {
      step: "build",
      name: "renameObject",
      tags: ["METADATA", "RENAME"],
    },
  );

  const copyCommand = new CopyObjectCommand({
    Bucket: bucket,
    CopySource: `${bucket}/${oldKey}`,
    Key: newKey,
  });

  await S3.send(copyCommand);

  S3.middlewareStack.remove("renameObject");
};

const S3 = new S3Client({
  region: "auto",
  s3ForcePathStyle: false,
  endpoint: "https://t3.storage.dev",
});

console.log("Rename object");
await renameObject(S3, bucket, object, newObject);
```

</TabItem>

Use the [`tigris-boto3-ext`](https://github.com/tigrisdata/tigris-boto3-ext)
package.

```bash
pip install tigris-boto3-ext
```

Use the `rename_object` helper for a single rename:

```python
import boto3
from tigris_boto3_ext import rename_object

s3 = boto3.client(
    "s3",
    endpoint_url="https://t3.storage.dev",
    aws_access_key_id="your-access-key",
    aws_secret_access_key="your-secret-key",
)

rename_object(s3, "my-bucket", "old-name.txt", "new-name.txt")
```

Use the `TigrisRename` context manager when you want to issue several renames on
the same client:

```python
from tigris_boto3_ext import TigrisRename

pairs = [
    ("a.txt", "renamed-a.txt"),
    ("b.txt", "renamed-b.txt"),
    ("c.txt", "renamed-c.txt"),
]

with TigrisRename(s3):
    for src, dst in pairs:
        s3.copy_object(
            Bucket="my-bucket",
            CopySource=f"my-bucket/{src}",
            Key=dst,
        )
```

destination, and `s3:GetObject` and `s3:DeleteObject` on the source.

## Renaming objects in the Dashboard

To rename an object in Tigris Dashboard:

1. Open the [Tigris Dashboard](https://console.storage.dev/) and log in.
2. In the side navigation, click "Buckets". Select the bucket, and find the
   object.
3. In the action menu next to the object, click "Rename".

![Tigris File Browser](/img/rename-obj-step-1.png)

4. Type the new name in the input field.
   ![Tigris Rename Object Popup](/img/rename-obj-step-2.png)

5. Click "Save".
6. Make sure that the list shows the new name.

![Tigris Rename Object Success modal ](/img/rename-obj-step-3.png)
